# 图片转 PDF 方向异常问题

> 状态：已修复（2026-10-17）

## 问题现象

使用“图片转 PDF”功能处理部分较大的手机或相机照片时，原本显示为竖向的图片可能在生成的 PDF 中变成横向，导致图片方向与预期不一致。

问题通常出现在带有 EXIF 方向信息的 JPEG 图片上。图片查看器会根据 EXIF Orientation 标记自动纠正显示方向，但 PDF 转换流程不一定会应用该标记。

## 根因分析

当前转换流程位于 `plugins/image_to_pdf.py` 的 `PDFWorker.run()` 中，主要步骤如下：

1. 使用 Pillow 打开源图片，并直接读取 `width`、`height`。
2. 对图片执行 `convert("RGB")` 或 `convert("RGBA")`。
3. 将处理后的图片保存为临时 JPEG。
4. 使用 PyMuPDF 将临时 JPEG 转换为 PDF 页面。

部分手机和相机照片的实际像素可能是横向的，例如 `1200 × 600`，但 EXIF Orientation=6 表示显示时应旋转 90 度，最终应作为 `600 × 1200` 的竖向图片显示。

当前流程没有先应用 EXIF Orientation。图片保存为临时 JPEG 后，方向标记可能丢失，而实际像素仍保持横向。之后 PyMuPDF 会按照临时 JPEG 的实际像素尺寸创建 PDF 页面，因此输出页面可能表现为横向。

这不是图片文件尺寸过大直接导致的旋转问题。大图片更容易来自手机或相机，而这类图片更常使用 EXIF 方向信息，所以现象看起来与图片大小有关。

## 修复建议

### 1. 在处理图片前应用 EXIF 方向

在 Pillow 读取图片后、进行尺寸扫描和缩放前调用：

```python
from PIL import ImageOps

with Image.open(file_path) as src_img:
    src_img.load()
    oriented_img = ImageOps.exif_transpose(src_img)
```

`ImageOps.exif_transpose()` 会将 EXIF Orientation 指定的旋转或翻转实际应用到像素，并清除已处理的方向信息。之后再执行颜色模式转换、缩放和临时 JPEG 保存。

### 2. 统一尺寸扫描和实际转换的方向

“智能缩放”当前会先扫描图片宽度。扫描阶段也必须使用应用 EXIF 方向后的图片尺寸，否则可能出现以下不一致：

- 扫描阶段认为图片宽度是原始横向宽度。
- 实际转换阶段将图片校正为竖向。
- 智能缩放结果和页面尺寸因此不符合预期。

应确保扫描阶段和实际转换阶段使用同一套方向校正逻辑。

### 3. 保持图片宽高比

当前 A4/A3 模式直接将图片缩放到固定的页面尺寸，可能把任意比例的图片强行拉伸为固定比例。建议按比例将图片适配到 A4 或 A3 页面，在页面中居中放置，而不是直接调整为 `(595, 842)` 或 `(842, 1191)`。

这属于独立于 EXIF 方向问题的改进项，但同样会影响 PDF 中图片的视觉效果。

## 建议的验证方式

增加带 EXIF 方向信息的回归测试，至少覆盖以下情况：

1. 创建一张实际像素为横向、EXIF Orientation=6 的图片，转换后 PDF 页面应为竖向。
2. 创建一张没有 EXIF Orientation 的横向图片，转换后仍应为横向。
3. 创建一张没有 EXIF Orientation 的竖向图片，转换后仍应为竖向。
4. 在“智能缩放”模式下验证方向校正前后的尺寸扫描结果一致。
5. 验证带透明通道的 PNG、普通 JPEG 和大尺寸 JPEG 均能正常转换。

## 实际修复方案

已在 `plugins/image_to_pdf.py` 的 `PDFWorker` 中完成以下修改：

1. 新增统一图片加载流程，在 Pillow 读取图片后调用 `ImageOps.exif_transpose()`，将 EXIF Orientation 旋转或翻转实际应用到像素数据，并在源图片关闭后返回独立图像对象。
2. 智能缩放的尺寸扫描阶段复用方向校正后的图片尺寸，实际转换阶段也复用同一套预处理逻辑，避免扫描结果和输出结果不一致。
3. A4、A3 模式改为创建固定尺寸的白色页面画布，将图片按原始宽高比缩放并居中放置，不再直接拉伸图片到页面尺寸。
4. A4、A3 临时 JPEG 使用 72 DPI 保存，使 PyMuPDF、img2pdf 和 Pillow 降级路径生成标准页面尺寸；其他页面模式保留原有分辨率行为。
5. 保留现有分批处理、临时文件清理和图像资源释放逻辑。

## 修复验证

新增 `test/test_image_to_pdf.py`，覆盖以下回归场景：

- EXIF Orientation=6 的横向像素图片转换为竖向 PDF 页面。
- 没有 EXIF 方向信息的横向图片保持横向。
- 智能缩放使用方向校正后的尺寸。
- A4、A3 页面保持标准页面尺寸，图片比例保持不变并留白居中。

验证结果：

- 图片转 PDF、共享工具和插件测试：39 项通过。
- `python -m py_compile plugins/image_to_pdf.py test/test_image_to_pdf.py`：通过。
- PyMuPDF、img2pdf、Pillow 三种 PDF 后端方向和 A4/A3 页面尺寸验证：通过。
- 用户手工验证：图片转 PDF 不再出现竖图旋转为横图的问题。

修复重点是：在图片进入缩放、颜色转换和 PDF 后端之前，统一调用 `ImageOps.exif_transpose()`，将方向元数据落实到像素数据。不要只依赖把 EXIF 信息复制到临时 JPEG，因为不同 PDF 后端对方向元数据的处理不一致，容易再次产生横竖方向错误。
