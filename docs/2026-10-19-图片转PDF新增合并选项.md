# 图片转PDF新增"是否合并"选项分析与实施

## 1. 需求

在"图片转PDF"插件的设置区，于"启用压缩"勾选项之后新增一个勾选项"是否合并"（默认不勾选）。

- **不勾选**：每张图片各自转换为一个独立的 PDF，输出文件路径可不填，输出文件名默认为 `<原图文件名>.pdf`（与原图同目录，或用户指定的输出目录）。
- **勾选**：沿用现有逻辑，将所有图片合并为一个 PDF，输出文件路径必填（未填时弹出保存对话框）。

## 2. 现状分析

- 插件文件：`plugins/image_to_pdf.py`，核心工作线程 `PDFWorker`，UI 类 `ImageToPDF`。
- 现有 `PDFWorker.__init__(files, output, page_size, compress=True, quality=85)` 只支持合并模式：批处理图片 → 临时 JPEG → 临时 PDF → 合并为 `output`。
- UI 设置区行布局（QGridLayout）：
  - 行0：页面大小
  - 行1：启用压缩
  - 行2：JPEG 质量
  - 行3：输出文件
- 配置持久化：`load_settings`/`save_settings` 映射 `page_size/compress/quality/output_file`，需新增 `merge` 键。
- i18n：`i18n/fragments/plugins_batch2.json` 与 `zh_CN.json`/`en.json` 需新增词条。

## 3. 设计决策

1. **Worker 默认合并=True**，保持旧调用（如测试 `PDFWorker(files, output, page_size, compress=False)`）语义不变；UI 默认传入勾选状态（默认 False），走独立转换路径。
2. **不合并路径**：逐张图片转换为独立 PDF。复用 `_prepare_image`、ICC 处理、页面尺寸逻辑；每张图生成临时 JPEG 再转单页 PDF，输出路径按原图文件名派生。
3. **输出目录派生**：若用户填写输出路径：
   - 是目录 → 直接使用；
   - 是文件路径 → 取其所在目录；
   - 未填 → 使用原图所在目录。
4. **预检查**：每张输出 PDF 转换前执行 `check_file_writable`，被占用则跳过并计入 `skipped`，不中断整批。
5. **进度**：合并模式 `len(files)+1`（含合并步骤）；独立模式 `len(files)`。
6. **消息**：独立模式成功消息 `plugin.image_to_pdf.msg.saved_multi`（含数量与输出目录）；跳过计数复用 `plugin.image_to_pdf.msg.skipped`。

## 4. 涉及文件

- `plugins/image_to_pdf.py`：Worker 新增 `merge` 参数与 `_run_individual`/`_convert_one_to_pdf`/`_individual_output_path`；UI 新增勾选框、行布局调整、retranslate、load/save settings、start_conversion 分支。
- `i18n/fragments/plugins_batch2.json`、`i18n/zh_CN.json`、`i18n/en.json`：新增 `label.merge`、`msg.saved_multi`。
- `docs/2026-10-19-插件设置项持久化方案.md`：配置清单新增 `merge` 行。

## 5. 风险与兼容

- 旧测试 `test_p3_image_to_pdf`、`test_image_to_pdf` 仍以合并模式调用 Worker，默认 `merge=True`，行为不变。
- 新增 i18n key 必须同步三处，否则 `check_i18n --refs` 报错。
- `merge=False` 时输出路径可空，避免弹出保存对话框。
