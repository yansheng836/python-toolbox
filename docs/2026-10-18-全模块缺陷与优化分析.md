# 全模块缺陷与优化分析

> 审查日期：2026-10-18
> 审查范围：`toolbox.py`、`config.py`、`main.py`、`settings_page.py`、`common/`（11 个文件）、`plugins/`（9 个插件）、`toolbox.spec`、`build.py`、`verify_packaging.py`、`test/` 与 CI 配置
> 状态：已完成审查，尚未修复
> 方法：按模块分派只读审查，高危结论均经人工二次核对源码确认

## 一、总体结论

项目整体架构清晰，共享组件层（`common/app_settings.py` 的原子写 + `.bak` 备份、`i18n.py` 的弱引用绑定、`empty_folder_cleaner.py` 的安全删除设计）实现严谨。但存在若干**高优先级缺陷**，集中在三类：

1. **数据安全**：文件去重插件存在越界扫描与误删风险，格式转换存在静默覆盖源文件。
2. **崩溃 / 假死**：Worker 线程信号遮蔽、删除操作占用 UI 线程、画布内存无上限。
3. **规则落空**：多处名为"保护"的实现（`check_file_writable`、主题适配选择器、样式表 `f` 前缀）实际失效，形成误导性死代码。

以下按严重程度分级。**高**为数据丢失、崩溃、功能失效；**中**为体验、性能、语义错误；**低**为规范与可维护性。

## 二、高严重度问题

### H1. 文件去重：删除操作在主线程执行，UI 冻结且不可取消

- 位置：`plugins/file_deduplicator.py:871-893`
- 问题：删除循环直接在 UI 线程运行，循环内无事件处理，也无可取消机制。批量删除数千文件时进度条不重绘、窗口无响应。
- 影响：与项目"长操作必须走 QThread"规则冲突；用户误以为程序卡死而强杀进程，导致删除中途中断。
- 修复：参照 `empty_folder_cleaner` 将删除移入 Worker，进度经信号上报，并响应取消标志。

### H2. 文件去重：`os.walk` 跟随 junction / symlink，可能扫描并删除根目录之外的文件

- 位置：`plugins/file_deduplicator.py:49-63`（扫描）、`:837-839`（删除）
- 问题：`os.path.islink()` 对 Windows junction 返回 `False`，`os.walk` 会进入 junction 指向的外部目录（如经典 `Application Data` 循环链接会死循环）；同时扫描未排除符号链接文件。排序后若链接排在前，保留的是链接，`os.remove` 删掉的却是真实数据文件。
- 影响：**不可逆数据丢失**；全项目风险最高的问题。
- 修复：改用 `os.scandir` + `entry.is_junction()`（`empty_folder_cleaner.py:36-48` 已正确实现，可反哺）；扫描时用 `os.path.islink()` 排除链接文件，保留决策强制选择真实文件。

### H3. 格式转换：同目录同格式转换静默覆盖源文件

- 位置：`plugins/image_format_converter.py:72`
- 问题：`out_path = f"{base}.{ext}"` 未加后缀。`a.jpg` 转 JPEG 且未指定输出目录时，源文件被 quality=85 重压缩后原地覆盖，无任何提示；批量中 `a.png`→JPEG 还会覆盖同目录已存在的 `a.jpg`（可能正是待处理文件，结果依赖处理顺序）。
- 影响：**源文件数据丢失**。
- 修复：与另两插件一致追加后缀（如 `_converted`），或在 save 前比较 `out_path` 与源路径 / 已有文件并跳过提示。

### H4. `check_file_writable` 以追加模式探测，凭空创建 0 字节文件

- 位置：`common/utils.py:172`；调用方 `plugins/image_to_pdf.py:113`、`plugins/pdf_merger.py:43`
- 问题：目标文件不存在时 `open(path, 'ab')` 直接创建 0 字节文件。本意是落实 Rule 9（写前检查占用），实际先在用户选择的输出路径留下空文件；若后续处理失败（如全部图片损坏），磁盘上残留 0 字节"成品"误导用户。
- 影响：Rule 9 产生反效果；`image_stitcher.py:243-259` 同源问题。
- 修复：先 `os.path.exists` 判断，不存在时仅验证父目录可写；或探测后删除探针文件。

### H5. `BaseWorker.finished` 信号遮蔽 QThread 内置信号

- 位置：`common/base_worker.py:26`
- 问题：`finished = pyqtSignal(bool, str)` 覆盖了 QThread 自带的**无参** `finished` 信号（`run()` 结束时由 C++ 发出）。这是 Qt 官方明确警告的反模式。
- 影响：任何对内置 `finished` 的隐式依赖（如 `worker.finished.connect(thread_cleanup)`、`deleteLater` 惯用法）会连到 Python 信号而非 C++ 信号，线程收尾逻辑静默失效；未来引入 QThread 生命周期管理时必踩坑。
- 修复：重命名为 `result = pyqtSignal(bool, str)`，全项目同步替换。

### H6. 图片拼接：画布像素总量无上限，峰值内存可达数十 GB

- 位置：`plugins/image_stitcher.py:288`、`:337`
- 问题：尺寸校验只限单边（`batch_w/batch_h ≤ 60000`），允许 60000×60000 RGBA 画布 = 14.4 GB；JPG 输出时 `canvas.split()[3]` 再生成 4 份单通道副本（+14.4 GB）。
- 影响：大图多张拼接时直接 `MemoryError` 或系统假死，外层 `except` 只报"stitch_failed"，用户不知原因。
- 修复：增加 `batch_w * batch_h` 像素预算检查（如 ≤ 200M px）提前报错；`:337` 改用 `canvas.getchannel('A')`（1 份副本替代 4 份）。

### H7. 扫描 / 删除期间可重入，旧 Worker 被覆盖导致崩溃

- 位置：`plugins/file_deduplicator.py:491-516`、`plugins/empty_folder_cleaner.py:558-587`、`:699-711`
- 问题：扫描期间"浏览"按钮与拖拽输入框未禁用，`start_scan` 无运行中守卫。`self.worker` 被重新赋值后旧 QThread 的 Python 对象失去引用，可能被 GC 触发 `QThread: Destroyed while thread is still running` 硬崩溃，且两套信号交叉写入同一 UI。
- 影响：进程崩溃。
- 修复：`start_scan` 开头检查 `self.worker and self.worker.isRunning()`，是则拒绝；扫描期间禁用 browse 与拖拽。

### H8. 图片压缩 / 格式转换：单个坏文件中止整批

- 位置：`plugins/image_compressor.py:132-135`、`plugins/image_format_converter.py:99-102`
- 问题：某文件损坏或被占用抛异常即跳出整个循环，已处理进度白费，只报最后一个错误。`image_scaler.py:117` 是 per-file 捕获，三个插件行为不一致。
- 影响：批量处理体验差；错误信息不完整。
- 修复：参照 scaler 改为 per-file try，统计成功 / 失败数，失败文件列入最终消息。

### H9. 图片插件 save 不传 EXIF / ICC，元数据整体丢失

- 位置：`plugins/image_compressor.py`、`image_format_converter.py`、`image_scaler.py` 的 save 调用；`common/utils.py:36-46`（`load_oriented_image`）
- 问题：`load_oriented_image` 已烘焙方向，但 save 不带 `exif=img.info.get('exif')`，相机型号 / GPS / 拍摄时间被清空；`image_format_converter.py:79-80` 主动删 ICC 以绕过"broken data stream"，导致广色域图偏色。
- 影响：元数据丢失；广色域图片偏色。同类问题见 `image_to_pdf.py:176-177`、`:185-192`。
- 修复：save 传 `exif`；ICC 丢失应通过完整读取源流解决，而非删除。

### H10. PNG 压缩级别映射错误，quality=100 时反而不压缩

- 位置：`plugins/image_compressor.py:122`
- 问题：`compress_level = 10 - quality/10`，quality=100 时 compress_level=0（zlib 零压缩），"压缩"出的 PNG 反而比原图大；quality 滑杆语义对 PNG 失效。
- 影响：PNG 压缩功能名存实亡。
- 修复：PNG 为无损格式，固定 `compress_level`（如 9）或将取值 clamp 到 6–9，并去除滑杆对 PNG 的影响。

### H11. PDF 插件未检查加密状态

- 位置：`plugins/pdf_merger.py:60-61`、`plugins/pdf_splitter.py:59`
- 问题：未检查 `doc.needs_pass` / 加密状态。加密 PDF 在 merger 中可能静默产出 0 页结果仍报"合并成功"，在 splitter 中 `load_page` 失败或产出 0 个文件。
- 影响：静默失败，结果错误且无提示。
- 修复：打开后检查 `needs_pass`，需密码时明确报错。

### H12. `settings_page.py` 为死代码，含必然抛错的信号定义，却仍被打包

- 位置：`settings_page.py`（整体）、`toolbox.spec:72,81`
- 问题：`toolbox.py:821` 已定义真正的 `SettingsPlugin`，`settings_page.py` 是重复旧版，全项目无任何 `import settings_page`。且 `settings_page.py:91` 的 `theme_changed = pyqtSignal(dict)` 定义在**非 QObject 类**上，一旦 `:235` 的 `emit` 被调用必然抛 `AttributeError`。`menu_system.py` 同属死代码，两者仍写入 spec 的 `datas` 与 `hiddenimports`。
- 影响：打包体积浪费；版本号混淆（该文件 `version="2.0.1"`，实际 2.0.6）；后续可能误改错文件。
- 修复：删除 `settings_page.py` / `menu_system.py` 及 spec 中对应条目。

## 三、中严重度问题

### M1. 文件列表全量重算 + 整图解码阻塞 UI 线程

- 位置：`common/file_list_panel.py:354-369`、`common/utils.py:36-46`
- 问题：`update_list()` 每次变化对所有行 × 所有列重新执行取值函数；`get_image_size` 经 `load_oriented_image` 做完整解码（`src_img.load()`）+ exif 转置 + 两次拷贝。添加 50 张图片 = 主线程同步解码 50 次全尺寸图像；每次增删都重算未变行（O(n²) 累积）。
- 修复：尺寸列改用 `Image.open` 只读头部 size + 手工按 orientation tag 换算；变更行增量刷新而非全表重建。

### M2. `load_oriented_image` 峰值内存约 3× 图像

- 位置：`common/utils.py:36-46`
- 问题：`src_img.load()` 全量解码 + `exif_transpose` 产生新图 + 无条件再 `.copy()`，三份像素数据同时存活。100 MP RGB 图峰值近 GB，所有图片插件每张图都走此路径。
- 修复：`exif_transpose` 返回的若非原对象则跳过 `copy()`：`result = ImageOps.exif_transpose(src); return result if result is not src else result.copy()`。

### M3. `get_pdf_pages` 异常路径泄漏文档句柄

- 位置：`common/utils.py:98-109`
- 问题：`doc = fitz.open(...)` 后若 `len(doc)` 抛异常（损坏 PDF），`doc.close()` 永不执行。
- 修复：改用 `with fitz.open(file_path) as doc:`（PyMuPDF 支持上下文管理器）。

### M4. 主题适配属性选择器为死代码

- 位置：`toolbox.py:1909-1914`
- 问题：`*[style*="color: #f1f5f9"]` 匹配的是 Qt 动态属性 `property("style")`，而非 styleSheet 字符串。全代码无任何 `setProperty("style", ...)`，这些选择器永不匹配。
- 影响：本意补救硬编码颜色的机制完全无效，是误导性死代码。
- 修复：删除，改为控件侧用 `Theme` 常量正确设置。

### M5. 主题按钮样式表缺 `f` 前缀

- 位置：`toolbox.py:928-944`、`:949-966`
- 问题：字符串内含 `{FONT_SIZE_16}`、`{FONT_WEIGHT_700}` 但无 `f` 前缀，花括号内容作为字面量输出，声明被 Qt 忽略。checked 态的字重加粗从未生效（被全局样式掩盖）。
- 修复：加 `f` 前缀。

### M6. `AnimatedButton` hover 硬编码深色主题

- 位置：`toolbox.py:145-158`
- 问题：`enterEvent` 用 `Theme.DARK['primary_hover']` 替换颜色，浅色主题下 hover 色错误；且 `update_style` 已用 `:hover` 伪状态处理，此处逻辑冗余。
- 修复：删除 enter / leaveEvent 的样式替换，仅靠 `:hover` 伪状态。

### M7. 启动阶段硬编码深色 + 主题切换后 QDialog 样式丢失

- 位置：`toolbox.py:1498-1533` vs `:1888-1966`
- 问题：`setup_ui` 硬编码 `#0f172a` / `#f1f5f9` 等深色样式，用户此前选浅色时启动先渲染深色再被 `init_theme` 覆盖，产生明显闪烁；初始样式含 `QDialog { background-color: #0f172a; }`，而 `apply_theme` 重设全局样式表时没有 QDialog 规则，主题切换后对话框背景样式丢失。
- 修复：`setup_ui` 不设最终样式，只依赖 `apply_theme`；`apply_theme` 补回 QDialog 规则。

### M8. 插件加载失败仅 `print` 到 stdout

- 位置：`toolbox.py:1567-1568`、`:1588-1589`
- 问题：`register_plugin` / `load_plugins` 捕获后只 `print`。PyInstaller windowed 模式无 stdout，用户完全无感知。
- 修复：接入日志或 `QMessageBox` 提示加载失败清单。

### M9. 欢迎页轮播定时器常驻空转

- 位置：`toolbox.py:467-471`
- 问题：`scroll_timer` 每 30 ms 永久运行，欢迎页不可见或卡片已隐藏时仍持续触发 `_do_auto_scroll` 空转。
- 修复：`hideEvent` / 页面切换时 `stop()`，`showEvent` 恢复。

### M10. `_get_favicon_path` 重复实现两份

- 位置：`toolbox.py:600-607`（静态方法）与 `:1765-1773`（实例方法）
- 问题：逻辑相同，违反代码复用规则。另 `setup_tray`（`:2042-2044`）用 `os.path.dirname(os.path.abspath(__file__))` 定位图标，未处理 frozen 模式（应用 `sys._MEIPASS`），打包后托盘永远显示 fallback 方块。
- 修复：统一为模块级函数；`setup_tray` 复用该函数。

### M11. 去重插件异常处理与删除语义问题

- 位置：`plugins/file_deduplicator.py:148-159`、`:161-176`、`:883`、`:178-179`、`:678-708`、`:880-884`、`:886-888`
- 问题：
  - 哈希函数捕获所有异常仅返回 `None`，导致 `run()` 中 `error.emit` 永不触发（死代码），不可读文件被无声排除。
  - `:883` 无条件 `os.chmod(S_IWRITE)` 清除只读属性，即使删除随后失败，属性已被改动。
  - `:178-179` `cancel()` 是死代码，大目录扫描无法中断。
  - `:678-708` `os.path.getctime` 未捕获 `OSError`，PyQt6 中 slot 未捕获异常会导致**进程直接终止**。
  - TOCTOU：`:880-884` 扫描与删除间隔内文件可能被替换为不同内容。
  - `:886-888` 文件不存在仍计为"删除成功"，统计口径误导。
- 修复：内层仅捕 `OSError` 并交由外层上报；仅在捕 `PermissionError` 后尝试 chmod；删除前对保留 / 删除文件做大小 + 快速哈希复核。

### M12. 删除操作不可恢复，无回收站选项

- 位置：`plugins/file_deduplicator.py:884`、`plugins/empty_folder_cleaner.py:212`

### M14. 未使用的配置项造成配置漂移

### M15. `verify_packaging.py` 与 spec 未同步

### M16. PDF 拆分：WebP 保存兼容性与 quality 语义

- 位置：`plugins/pdf_splitter.py:92-93`、`:90-91`

- 修复：经 PIL 保存（`pix.tobytes("png")` → `Image`）；拆分 DPI 与 JPG 质量分离，或改标签为"清晰度"。

### M17. 对话框 / 消息框 theme 缺省强制亮色

## 五、跨模块共性问题

1. **"保护性"代码实际失效**：`check_file_writable`（就地创建空文件）、主题属性选择器（永不匹配）、样式表缺 `f` 前缀——三处代码看似提供保护，实则无效，比没有更危险，因为维护者会误以为已被覆盖。
2. **异常处理两极化**：底层（哈希、页数估算、`getctime`）静默吞异常导致上层 `error.emit` 成死代码；顶层则单点异常中止整批。缺少"per-item 捕获 + 批量汇总"的统一模式。
3. **Worker 规范未统一**：`image_stitcher` / `image_to_pdf` 用 `BaseWorker`（信号名遮蔽隐患），`file_deduplicator` 干脆绕开；取消机制、防重入守卫、进度语义各插件各异。
4. **规则 7（文本可复制）与规则 8（响应式）仍有遗漏**：多处裸 `QLabel`、`addStretch()`、`setFixedHeight()`。
