# 侧边栏导航排序与隐藏功能可行性分析

> 日期：2026-10-18。状态：已实现（改动清单与验证结果见文末「九、实施记录」）。
> 需求：在设置页新增「导航栏管理」——1) 按自定义顺序排列左侧导航项；2) 隐藏不常用的导航项；首页功能卡片同步调整。目标是把常用工具放前面、不常用的收起来。

## 结论

**可行，且属于低成本改造。** 现有架构已经把「插件注册（实例化页面）」与「导航项展示」分得比较开：

- 导航项只是一个 `SidebarButton`，页面本身在 `QStackedWidget` 里，按 `plugin.scroll_area` 定位（`toolbox.py:1385-1391`），**与顺序无关**
- 因此调整顺序/隐藏**不需要重建插件实例、不需要改堆栈索引**，只动侧边栏按钮的排列与可见性
- 配置已有成熟的持久化通道（`common/app_settings.py` 的 INI），加一个 `[nav]` 段即可

预估工作量 2–3 人日，无新增依赖，不改动任何插件代码。

## 一、现状分析

### 1.1 顺序的唯一来源

| 位置 | 作用 |
|---|---|
| `config.py:20-112` `PLUGIN_MODULES` | 插件清单单一数据源，每项带 `order`（越小越前）与稳定 `id` |
| `toolbox.py:1346-1351` `load_plugins()` | 按 `order` 排序后依次 `register_plugin()` |
| `toolbox.py:1296-1299` `register_plugin()` | 创建 `SidebarButton` 并 `nav_layout.addWidget(btn)` —— **顺序即创建顺序** |
| `config.py:114-118` `FEATURE_MODULES` | 由 `PLUGIN_MODULES` 派生，`order < 999` 的才上首页 |

约定：`order >= 999` 是「固定末尾、不参与首页展示」的哨兵值（当前只有「设置」用它）。这个约定正好可以复用为「不可隐藏、不可排序」。

### 1.2 侧边栏结构

`toolbox.py:1221-1225`：

```python
self.nav_widget = QWidget()
self.nav_layout = QVBoxLayout(self.nav_widget)   # 插件按钮都挂在这里
```

按钮**没有按 id 建索引**（`register_plugin` 里是局部变量），要重排/隐藏必须先补一个 `self.nav_buttons: Dict[str, SidebarButton]` 注册表。

折叠动画作用于 `self._sidebar_children`（`toolbox.py:1245-1248`），其中只有 `nav_widget` 整体，**不会覆盖单个按钮的 visibility**，因此隐藏按钮与折叠/展开不冲突。

### 1.3 首页卡片

`WelcomePage.setup_ui()` 在 `toolbox.py:676-739` 直接遍历 `PLUGIN_MODULES` 创建卡片，并把标签追加进 `self.text_labels` / `self.desc_labels` / `self.separators`；`retranslate_ui()`（`toolbox.py:573-588`）用 `zip(self._feature_ids, self.text_labels, ...)` 重放语言。

→ 重建卡片时必须**同时清空这三个列表并重建 `_feature_ids`**，否则列表会越积越长、语言切换重放错位（这是本次改造唯一的隐蔽坑）。

### 1.4 设置页

- 真正的设置页是 `toolbox.py:753` 的 `SettingsPlugin`（`config.py:103-111` 指向 `toolbox.SettingsPlugin`）
- `settings_page.py` 是**死代码**（全仓库无 import），不要往里加东西

### 1.5 配置持久化

`common/app_settings.py`：

- `_DEFAULTS`（`:64-68`）声明默认节/键，`_fill_defaults()`（`:199-206`）只补缺失、不覆盖
- `reset()`（`:259-264`）清空全部已保存值 —— 新增的导航配置会**自动**被「恢复默认设置」覆盖
- `interpolation=None`，值里的 `%`、逗号都安全

## 二、设计决策

| 决策点 | 方案 | 结论 |
|---|---|---|
| 配置存哪 | 新增 INI `[nav]` 段 vs 单独 JSON 文件 vs QSettings | **INI**，与现有语言/主题/窗口一致，且 README 已文档化 |
| 配置格式 | `order=a,b,c` + `hidden=x,y`（逗号分隔） vs 单键 JSON | **逗号分隔**，纯 ASCII id，可手改，解析失败易回退 |
| 何时写入 | 启动即写全量顺序 vs 用户改动才写 | **改动才写**；未写过时顺序完全由 `config.py` 决定，新版本新增插件能自然插到正确位置 |
| 隐藏的含义 | 不创建按钮 / 创建后 `setVisible(False)` / 不加载插件 | **创建后隐藏**。插件仍加载、页面仍在堆栈里，改动最小、切回即用 |
| 设置页能否被隐藏 | 可以 / 不可以 | **不可以**（`order>=999` 视为固定项），否则用户可能把自己锁死在无入口状态 |
| 生效时机 | 点「保存」 vs 即时生效 | **即时生效 + 即时持久化**，操作反馈最直接，也免去「保存/取消」两套状态 |
| 排序交互 | 上移/下移按钮 vs 拖拽 vs 两者 | **拖拽（`QListWidget` InternalMove）+ 复选框**，另配「全部显示」「恢复默认」两个兜底按钮 |
| 首页卡片是否跟随 | 跟随隐藏集 vs 全部展示 | **跟随**：隐藏的就不出现在首页，与「收起来」的语义一致 |

### 交互形态（设置页新增卡片）

```text
┌ 导航栏管理 ─────────────────────────────┐
│ 拖拽调整顺序，取消勾选可隐藏该工具        │
│ ┌─────────────────────────────────────┐ │
│ │ ☑ 🗜️ 图片压缩                        │ │
│ │ ☑ 🔁 图片格式转换                    │ │
│ │ ☐ 🧹 文件去重                        │ │
│ │ ☐ 🗑️ 空文件夹清理                    │ │
│ │ …                                   │ │
│ └─────────────────────────────────────┘ │
│ [ 全部显示 ]  [ 恢复默认 ]                │
└─────────────────────────────────────────┘
```

设置项自身不出现在列表里（固定末尾、不可隐藏）。

## 三、实现方案

### 3.1 新增纯逻辑模块 `common/nav_config.py`

把「合并顺序」从 UI 里抽出来，便于单测（符合项目 Code Reuse 规则）：

```python
PINNED_ORDER = 999          # 与 config.py 的哨兵值一致

def available_ids(plugin_modules): ...        # 参与排序的 id，按 config 顺序
def parse_list(value): ...                    # "a,b,c" -> ["a","b","c"]，容错
def resolve_order(all_ids, saved_order):
    """saved_order 中仍存在的 id 优先；未知 id 丢弃；未出现的 id 按默认顺序追加"""
def resolve_hidden(all_ids, hidden_ids): ...  # 过滤未知 id、去重
def load_nav_state(settings, plugin_modules): ...   # 读 INI + 合并，返回 (order, hidden)
def save_nav_state(settings, order, hidden): ...    # 写 INI + save()
```

`resolve_order` 的合并规则是**版本升级兼容的关键**：

- 老配置里存在、但新版本已删除的 id → 丢弃（打印一行提示）
- 新版本新增、老配置里没有的 id → 按 `config.py` 的 `order` 插到末尾

### 3.2 `ToolboxWindow` 侧改造

| 改动点 | 说明 |
|---|---|
| `register_plugin()` | 保存 `self.nav_buttons[plugin.id] = btn` |
| 新增 `rebuild_navigation()` | 按解析结果对**已存在的按钮**做 `removeWidget` + `insertWidget(i, btn)`，并 `setVisible(True/False)`；不销毁重建，保留 `setChecked` 状态与信号连接 |
| `switch_plugin()` | 目标是隐藏项时拒绝切换（防程序化调用） |
| `switch_to_welcome()` | 遍历时跳过不可见按钮（逻辑上无影响，加防御） |
| `apply_theme()` | 已用 `findChildren(SidebarButton)`（`:1712-1714`），重排后仍生效，无需改 |
| `retranslate_ui()` | 已按 `nav_layout` 遍历（`:1813-1818`），重排后仍生效，无需改 |
| `reset_defaults()` 之后 | 追加 `rebuild_navigation()`，让导航恢复默认 |

伪代码：

```python
def rebuild_navigation(self):
    order, hidden = nav_config.load_nav_state(self.app_settings, PLUGIN_MODULES)
    for i, pid in enumerate(order):
        btn = self.nav_buttons[pid]
        self.nav_layout.removeWidget(btn)
        self.nav_layout.insertWidget(i, btn)
        btn.setVisible(pid not in hidden)
    if self.current_plugin in hidden:
        self.switch_to_welcome()
    self.welcome_page.rebuild_feature_cards([p for p in order if p not in hidden])
```

调用时机：`load_plugins()` 末尾一次；设置页每次改动后一次。

### 3.3 `WelcomePage` 侧改造

新增 `rebuild_feature_cards(visible_ids)`：

1. 清空 `features_layout` 中所有 widget（`takeAt` + `deleteLater`）
2. 清空 `self.text_labels` / `self.desc_labels` / `self.separators`，重建 `self._feature_ids`
3. 按 `visible_ids` 重建卡片（把现有 676-739 的建卡逻辑抽成 `_create_feature_card(pid)` 复用）
4. `horizontalScrollBar().setValue(0)`，`_scroll_direction = 1`，重置 `_at_end_pause`，避免轮播定时器指向旧状态
5. `visible_ids` 为空时放一条提示文字（i18n），避免空白轮播区

`update_theme()` / `retranslate_ui()` 依赖第 2 步重建后的列表，自然正确。

### 3.4 设置页新增卡片

在 `SettingsPlugin.create_ui()` 的「通用设置」与「关于」之间插入 `Card(t("settings.card.nav"))`：

- `QListWidget`：`setDragDropMode(InternalMove)`、`setMinimumHeight(240)`、`Expanding` 尺寸策略（符合响应式规则）
- 每项 `QListWidgetItem`：`setCheckState()` + 文本 `f"{icon} {t('plugin.{id}.name')}"`，`setData(Qt.UserRole, pid)`
- 信号：`model().rowsMoved` → 持久化顺序；`itemChanged` → 持久化隐藏集（重建列表时用 `blockSignals` 防抖）
- 按钮：`全部显示`（清空 hidden）、`恢复默认`（清空 `[nav]` 两键）
- `update_theme()` 补列表与按钮配色；`retranslate_ui()` 重建列表项文本

## 四、边界情况

| 场景 | 处理 |
|---|---|
| 全部工具被隐藏 | 侧边栏只剩「首页 / 设置」；首页显示 `welcome.no_tools_hint`；仍可通过菜单 `工具 → 设置 (Ctrl+S)` 或侧边栏进入设置恢复 |
| 配置里出现已删除插件的 id | `resolve_order` 丢弃，打印 `print()` 提示（符合异常处理规则：报告而非静默） |
| 新版本新增插件 | 自动追加到末尾并默认可见 |
| 配置值损坏（如 `order=,,,`） | `parse_list` 过滤空项；全空则退回 `config.py` 默认顺序 |
| 当前停留的页面被隐藏 | `rebuild_navigation()` 检测到后 `switch_to_welcome()` |
| 侧边栏折叠状态下改动 | 按钮 `setVisible` 与 `nav_widget` 的可见性相互独立，展开后状态正确 |
| 语言切换 | 侧边栏走 `retranslate_ui`，列表项与首页卡片各自重建，均为既有机制 |
| 恢复默认设置 | `AppSettings.reset()` 清掉 `[nav]` → 重建导航恢复默认顺序与全部可见 |
| 插件加载失败 | 失败插件不在 `self.plugins`，也不会出现在列表里，天然不参与排序 |

## 五、风险

| 风险 | 等级 | 说明与对策 |
|---|---|---|
| 首页卡片列表累积/错位 | 中 | `text_labels` 等列表当前只增不清；重建必须同步重置（见 3.3 第 2 步），并加测试 |
| `QListWidget` 拖拽 + 复选框的信号风暴 | 中 | 重建/回填时 `blockSignals(True)`；持久化做 200ms 防抖亦可 |
| 深浅主题下列表可读性 | 中 | 列表与复选框样式全部用 `Theme` 常量，两种主题各验一遍（项目硬规则 3） |
| 版本升级导致顺序错乱 | 低 | `resolve_order` 合并规则 + 单测覆盖 |
| 折叠动画期间重排 | 低 | 重排只改布局位置与 visibility，不触碰宽度动画 |
| 用户找不到被隐藏的工具 | 低 | 设置列表始终列全量工具；菜单 `Ctrl+S` 兜底 |

## 八、非目标（本期不做）

- **插件懒加载**：隐藏的插件仍会实例化。改成按需创建属于更大重构（涉及 `get_widget()` 调用时机与错误处理），收益有限

- **快捷键绑定到具体工具**：与本期目标无关
- **多套布局配置（如「工作模式 A/B」）**：先验证单套配置的使用率

### 9.2 与方案的差异

| 原方案 | 实际实现 | 原因 |
|---|---|---|
| 首页空态提示（3.3 第 5 步） | 新增 `WelcomePage.empty_hint` 标签，与轮播区互斥显示 | 卡片全被隐藏时首页不至于空白 |
| 列表高度 | 按 `sizeHintForRow(0)` × 条目数 + 16 计算，上限 360px | 固定「36px/行」与实际行高（26px）不符，会留白 |
| 隐藏集防护（3.2） | 用 `ToolboxWindow._hidden_plugins` 集合判断 | `isVisible()` 在窗口未显示或侧边栏折叠时不可靠 |
| 「恢复默认」按钮 | 设置页按钮只清 `[nav]`（`reset_nav_state`）；原有「恢复默认设置」走 `AppSettings.reset()` 顺带清空 | 两者语义不同（局部 vs 全局），分开实现 |
| 语言切换（3.5） | 设置页 `retranslate_ui()` 重建列表项文本 | `QListWidgetItem` 不是 QWidget，无法用 `i18n.bind()` 绑定 |
| 固定项判定 | 复用 `PINNED_ORDER = 999`，`manageable_ids()` 排除固定项 | 即使手工在 `hidden` 写入 `settings` 也不会生效，双重保险 |
